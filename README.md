# AF MASTER

تطبيق تعليمي عربي مباشر، مبني بملفات HTML وCSS وJavaScript عادية في جذر المشروع. واجهة الموقع لا تحتاج Node.js أو npm أو React أو Parcel أو خطوة build؛ ملفات Firebase SDK تُحمّل من CDN.

## تشغيل محلياً

افتح `index.html` في المتصفح، أو استخدم خادماً محلياً بسيطاً لدعم ES modules وService Worker:

```powershell
py -m http.server 8000
```

ثم افتح `http://localhost:8000`. تسجيل Google وميزات Firebase تحتاج اتصالاً بالإنترنت ونطاقاً مسموحاً في إعدادات Firebase Authentication.

## النشر على GitHub Pages

1. ادفع ملفات المشروع إلى فرع GitHub.
2. من **Settings → Pages** اختر **Deploy from a branch**، وحدد الفرع ومجلد **/(root)**.
3. فعّل **Google** كمزوّد تسجيل دخول، وأضف نطاق GitHub Pages إلى **Firebase Console → Authentication → Settings → Authorized domains**.

لا تنشئ مجلد `dist` ولا تشغّل عملية build للموقع. ملفات النشر المباشر تشمل `index.html` و`styles.css` و`app.js` و`firebase-config.js` و`logo.jpeg` و`manifest.webmanifest` و`sw.js` وفيديو المقدمة `WhatsApp Video 2026-11-12 at 11.29.58 PM.mp4`.

إعداد Firebase للويب داخل `firebase-config.js` إعداد عميل عام وليس مفتاحاً سرياً؛ الحماية الفعلية تعتمد على Authentication وFirestore Security Rules. لا تضف مفاتيح Admin SDK أو كلمات المرور إلى ملفات الويب.

## Firebase وFirestore

كل بيانات المنصة تُقرأ وتُكتب مباشرةً في Firestore من التطبيق، وتُزامَن عبر `onSnapshot`. تسجيل الدخول يتم عبر Firebase Authentication، ولا يستدعي التطبيق Cloud Functions. انشر قواعد الأمان والفهارس وسياسات الحذف التلقائي بعد مراجعتها:

```powershell
firebase login
firebase use YOUR_FIREBASE_PROJECT_ID
firebase deploy --only firestore:rules,firestore:indexes
```

تشمل الكتابات المباشرة التسجيل وكود الطالب والإحالات والمشاركة والمحتوى والإعلانات والتحذيرات والحظر ورسائل المحادثة. قواعد Firestore تحصر إدارة المحتوى والإعلانات والحسابات على UIDs المشرفين المعتمدة. يحفظ `publicStats/catalog` العدد الحقيقي للمنصات ويزامنه المشرف مباشرةً، بينما يستطيع المستخدم المسجل قراءة هذا العدد فقط. إعدادات `expiresAt` تفعّل Firestore TTL لرسائل الشات العام فقط؛ تبقى الإعلانات حتى يخفيها المشرف، من دون مهمة مجدولة أو Cloud Function.

لتفعيل دخول الطلاب بالكود، فعّل مزوّد **Email/Password** في **Firebase Console → Authentication → Sign-in method** إلى جانب Google. ينشئ التطبيق اعتماد Email/Password داخلياً مرتبطاً بنفس UID لحساب Google؛ لا تُرسل رسائل بريد. الكود الظاهر للطالب عشوائي من 24 رقماً، ويُحفظ في `profiles/{uid}/privateAuth/login` بحيث لا يستطيع قراءته إلا صاحب الحساب. كما يحجز التطبيق الكود في `loginCodes/{code}` لضمان عدم تكراره؛ لا يمكن قراءة هذا الربط إلا لصاحب الحساب ولا يمكن الاستعلام عن المجموعة. يجب على الطالب حفظ الكود بسرية.

تسجيل المشرف يتم من زر **المتابعة باستخدام Google** نفسه. حظر الطالب يوقف وصول حسابه إلى بيانات المنصة عبر Firestore؛ ولا يعطّل حسابه في Google Authentication.

### الاختبار على محاكيات Firebase المحلية

يتطلب تشغيل Auth وFirestore Emulator تثبيت Java 21 وFirebase CLI. من مجلد المشروع شغّل:

```powershell
firebase emulators:start --only auth,firestore --project demo-af-master
```

شغّل خادماً محلياً للملفات وافتح `http://127.0.0.1:8000/?emulator=1`. يتصل التطبيق بالمحاكيات فقط عند استخدام هذا الخيار على `localhost` أو `127.0.0.1`، ويستخدم معرّف مشروع ومفتاح API تجريبيين؛ لا تستخدم حسابات أو بيانات حقيقية في الاختبار. يُتجاهل الخيار على أي نطاق منشور، وتُحفظ بيانات الاختبار في المحاكيات المحلية فقط.

## المزايا والحدود

- تسجيل الطلاب عبر Google؛ يحفظ الطالب اسمه والهاتف والصف والمسار مباشرةً في `profiles/{uid}`. تمنع قواعد Firestore تعديل بيانات طالب آخر، وتحجز الاسم ورقم الهاتف لمنع التكرار.
- تظهر للطالب فقط خطوة اشتراك قناة واتساب بعد الدخول أو إنشاء الحساب. يفتح الزر القناة، وبعد ضغط «اشتركت، متابعة» تُحفظ `whatsappChannelJoined` في ملفه على Firestore فلا تظهر الخطوة مجدداً. هذا تأكيد ذاتي من الطالب، ولا يثبت التطبيق عضوية القناة عبر واتساب.
- يمكن للطالب دخول الحساب أول مرة عبر Google، ثم الدخول لاحقاً باستخدام كود رقمي سري من 24 رقماً. الحسابات القديمة يمكنها إنشاء/تفعيل الكود من إعدادات الحساب. لا تفرض عملية الدخول حداً للأجهزة أو موافقات الأجهزة.
- تظهر مقدمة الفيديو عند تحميل التطبيق. يبدأ التشغيل بالصوت تلقائياً حيث يسمح المتصفح؛ إذا منع التشغيل التلقائي، يلزم الضغط على زر التشغيل، ولا يوجد تخطٍ.
- تحديث الصف والمسار يتم مباشرةً في Firestore. فتح المحتوى يتطلب إضافة 10 أرقام واتساب مختلفة؛ يُحتسب كل رقم فور حفظه، ولا يُشترط إرسال رسالة أو تسجيل المستلمين.
- تنظيم المحتوى السحابي في `courses` للمنصات و`chapters` للفصول أو أقسام الامتحانات، وربط `lessons` بها عبر `courseId` و`chapterId`. يستخدم التطبيق `audienceKeys` لتصفية المحتوى حسب صف الطالب ومساره في استعلامات Firestore، وتُحدّث البيانات القديمة تلقائياً عند تشغيل لوحة المشرف. يستطيع المشرف إضافة المنصات والفصول والدروس والأسئلة والإجابات، وتعديلها أو ترتيبها أو حذفها؛ حذف المنصة يحذف معها فصولها ودروسها. تظهر التحديثات عبر `onSnapshot`.
- تبقى الإعلانات ظاهرة للطلاب حتى يخفيها المشرف من صفحة الإعلانات. تُحفظ وتُزامَن مباشرةً في Firestore.
- الشات العام ومحادثات الدعم تستخدم `onSnapshot` مباشرةً. تنتهي رسائل الشات العام بعد 24 ساعة؛ محادثات الدعم وسجلها لا تنتهي تلقائياً، وتظهر للطالب مهلة 24 ساعة للرد على آخر رد للمشرف مع زر بدء محادثة جديدة بعدها. صندوق وارد المشرف يعرض أحدث رسالة لكل محادثة. عند فتح صندوق الوارد، يحاول التطبيق إزالة مؤقت الانتهاء من رسائل الدعم القديمة التي ما زالت موجودة؛ الرسائل التي حذفها TTL قبل هذا التحديث لا يمكن استعادتها.
- لا يُحفظ رقم واتساب الخام؛ تُستخدم بصمة SHA-256 لمنع تكرار الرقم، وإرسال الدعوة عبر واتساب اختياري. البصمة ليست تشفيراً ولا تمنع تخمين الأرقام؛ التحقق من الصيغة يتم من جهة العميل ولا يمكن إثبات أن الرقم فعّال أو منع التلاعب بالكامل دون خادم موثوق.
- تواصل الطالب مع المشرف خاص ودائم، وشات الطلاب مشترك؛ تتحدث الرسائل لحظياً، وتُحذف رسائل الشات العام فقط عبر Firestore TTL عند انتهاء صلاحيتها.
- يعمل Service Worker ضمن مسار الموقع، بما في ذلك مسار مستودع GitHub Pages.
- لا يخزّن التطبيق بيانات الحساب أو المنصة في `localStorage` أو `sessionStorage`؛ حالة العرض الحية مؤقتة في ذاكرة الصفحة، ويتولى Firebase Authentication إدارة جلسة تسجيل الدخول.
